Airlock

No serious deployment gives production credentials to an LLM. But agents need to run code that touches real systems — databases, APIs, payment processors. Airlock solves this by keeping secrets completely isolated from the model's context window.

How It Works

Agents submit Python code to Airlock via a REST API. Airlock verifies identity and code integrity using HMAC-SHA256, injects the required credentials into an isolated Python worker, executes the code, scans the output to strip any leaked secrets, and returns the sanitized result.

The agent never sees the actual credential values — only opaque profile keys. The credentials exist only inside the sandbox, for the duration of execution.

Security Model

  • AES-256-GCM encryption at rest for all stored credentials
  • HMAC-SHA256 verification proves code hasn't been tampered with in transit
  • Scoped profiles — each profile exposes only selected credentials
  • Time-limited access with instant revocation
  • Output scanning removes secrets before results reach the agent
  • Non-root, resource-limited sandboxed execution

Agent Integration

Airlock is designed for self-onboarding. A static SKILL.md document and a dynamic GET /skill.md endpoint give agents instance-specific guidance. Agents can declare Python package requirements via API, and packages persist across container restarts.

The LLM pause/resume capability lets scripts call llm.complete(prompt) to pause execution and request agent reasoning mid-run — cleanly separating deterministic processing from LLM interpretation.

Deployment

Ships as a single Docker container: Svelte frontend for admin management, Python FastAPI backend, SQLite for encrypted storage. One-click deploy targets for Render, Railway, and Fly.io. Mount a persistent /data volume and it maintains state across restarts.

Stack

Python (FastAPI) · Svelte · SQLite · Docker
