Nexus

Agents need data from the outside world — emails, calendar events, meeting transcripts — but external systems don't speak agent. Nexus sits between third-party services and OpenClaw, handling the messy work of receiving, normalizing, and delivering data so agents can focus on what to do with it.

How It Works

Third-party systems push webhooks to Nexus. Each webhook hits a structured endpoint:

POST /api/webhook/{agentName}/{source}/{type}?code={functionKey}

Nexus processes the incoming data — normalizing formats, fetching full payloads when a webhook only contains an ID, and enriching metadata. Once processing is complete, Nexus either pushes the content directly to OpenClaw or exposes an endpoint for OpenClaw to pull from, depending on the deployment's requirements.

Current Integrations

  • Microsoft Graph — email and calendar events
  • Fireflies.ai — meeting transcripts

Storage

Structured metadata lives in table storage with type-based partitioning and agent routing. Large content — email bodies, documents, full transcripts — goes to blob storage. This separation keeps queries fast while handling arbitrarily large payloads.

Deployment

Deployed via GitHub Actions — push to main and it's live. The integration-specific processing logic makes it straightforward to add new sources without touching the core routing.

Stack

C# · Azure Functions · Table Storage · Blob Storage
